One codebase. Three clouds, no branching.

Snip ships as a static front end plus a single lightweight redirect function. Point it at whichever platform your team already pays for.

Microsoft Azure

Deploy the front end to Static Web Apps and the redirect logic as an Azure Function bound to the same route.

  • az staticwebapp create
  • Cosmos DB for link storage
  • Front Door for edge caching
Amazon Web Services

Host on S3 behind CloudFront, with redirects handled by a small Lambda@Edge function.

  • aws s3 sync ./dist
  • DynamoDB for link storage
  • CloudFront for edge caching
Google Cloud

Serve from Firebase Hosting and resolve redirects with a Cloud Run service on the same domain.

  • firebase deploy
  • Firestore for link storage
  • Cloud CDN for edge caching

Built to be moved, not just hosted.

01

Stateless redirects

The redirect function only reads a key-value pair, so it maps cleanly onto any provider's function runtime.

02

Swappable storage

A thin storage interface sits in front of Cosmos DB, DynamoDB, or Firestore — change one config value to switch.

03

Custom slugs

Reserve a memorable path for a link, or let Snip generate a short, collision-checked code automatically.

04

Click insight

Every redirect logs a timestamp and referrer so you can see how a link performs, wherever it's hosted.
